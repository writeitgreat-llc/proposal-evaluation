{# ── Analytics tracker ───────────────────────────────────────────────────── Goes at the foot of , and ONLY on the public funnel pages — it is included from base_public.html and from nowhere else. See that file for the scope boundary and why it is drawn where it is. Measures pages, engaged time, scroll depth, clicks off this site, and posts them to our own /e endpoint on this same domain. Stores NOTHING on the device. No cookie is read or written here; the only cookie in this feature is set by the server, only after an explicit opt-in, and this file never touches it. That is what lets the baseline measurement run for everyone without a consent gate — see _consent.html for the tier that does need one, and _integration/CONTRACT_ANALYTICS.md for the reasoning. Design notes worth knowing before editing: * The page identity comes from the SERVER (`analytics_path`), not from location.pathname. This app serves tokenised URLs — /author/reset-password/ is one of the instrumented pages — and sending the literal path would put a live reset token into a request body. The server sends the matched Flask route instead, so the token never leaves the page at all. (analytics_collect.normalise_route re-derives the same thing server-side, so a forged beacon cannot smuggle one in either.) * Engaged time is an idle-gated accumulator, not heartbeat pings. A heartbeat every 5s would be ~10 extra requests per pageview to answer a question one number can answer. Time only accrues while the tab is visible AND the visitor has done something in the last 30 seconds, so a tab left open over lunch does not report as forty minutes of reading. * Delivery is on `visibilitychange`→hidden and `pagehide`. There is deliberately no `unload` handler: `unload` disables the back/forward cache, is unreliable on iOS, and is on a standards path to removal. * Nothing the visitor typed is ever an event. No field values, no search terms. The only string this file ever sends about the page is a route the server chose. * Everything is wrapped. An analytics bug must never be the reason a page breaks — least of all a login page — so every entry point is inside a try/catch and failure is silent. #}
